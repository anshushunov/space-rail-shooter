# Space Rail Shooter — дизайн прототипа

Дата: 2026-09-04. Статус: утверждён владельцем, готов к плану реализации.

## 1. Цель

Учебный прототип: 3D-корабль летит вперёд по космосу и стреляет во врагов.
Основная цель проекта — освоить пайплайн Blender → Godot и наработать набор
собственных low-poly моделей. Игра — средство, а не продукт.

Референсы по визуальному стилю: Fur Squadron Phoenix, Whisker Squadron:
Survivor. Современный стилизованный low-poly: гладкие формы, палитровые
текстуры, яркие эмиссивные детали.

## 2. Принятые решения

| Вопрос | Решение | Отклонённые варианты |
|---|---|---|
| Стиль | Стилизованный low-poly с палитрой | Ретро flat-shading, PBR sci-fi, wireframe |
| Движение | Прямой бесконечный полёт, мир едет на игрока | Rail по сплайну, гибрид |
| Стек | Godot 4.7 mono + C# | GDScript, другие движки |
| Уровень владельца в Blender | Ноль | — |
| Scope | Минимальная петля | Петля с прогрессией, только связка |
| Кто моделит | Claude через Blender MCP, владелец валидирует и правит руками | Владелец моделит сам под сопровождением, поочерёдно |
| Полёт в Godot | Корабль стоит у начала координат, мир движется по -Z | Корабль летит, камера следует |
| Хранение моделей | Скрипт генерации + .blend как источник правды после передачи | Только скрипты, только .blend |

## 3. Структура проекта

```
prototype-blender/
├── game/                      # проект Godot 4.7 (project.godot здесь)
│   ├── scenes/                # .tscn: Main, Player, EnemyDrone, EnemyShooter, Asteroid, Bullet, HUD
│   ├── scripts/               # C#, один класс на сцену
│   ├── assets/
│   │   ├── models/            # .glb из Blender, только экспорт, руками не правится
│   │   ├── textures/          # палитра и прочие .png
│   │   └── sky/               # скайбокс
│   └── tests/                 # xUnit-тесты чистой логики
├── art/
│   ├── blender/
│   │   ├── scripts/           # генераторы моделей .py
│   │   ├── *.blend            # источник правды после передачи владельцу
│   │   └── palette.png        # одна палитра на все модели
│   ├── refs/                  # референсы, концепты, превью
│   └── export.py              # единый экспорт .blend → game/assets/models
├── docs/
│   ├── superpowers/specs/     # этот документ и последующие
│   └── style-guide.md         # палитра, полигонаж, именование
├── CLAUDE.md
└── README.md
```

Правила:

- В `game/assets/models` лежат только экспортированные файлы. Правки только
  в Blender, затем переэкспорт.
- Одна палитра `palette.png` на всю игру. Модели красятся через UV в её
  ячейки. Отдельных текстур на модель нет.
- Godot-проект вложен в `game/`, чтобы редактор не индексировал арт и
  документы.
- Solution C# в `game/`, тесты в отдельном проекте `game/tests/` на xUnit.

## 4. Игровые сущности

**Main** — корневая сцена. Дети: `World`, `Player`, `Spawner`, `HUD`.
Читает `GameState` из autoload-ноды `Session`.

**GameState** — чистый C#-класс без Node. Хранит скорость мира, HP игрока,
счёт, флаг «игра идёт». Единственное место изменения этих чисел. Методы:
`TakeDamage(int)`, `AddScore(int)`, `Restart()`, `Tick(double delta)` для
роста скорости. Тестируется без движка.

**Player** — `CharacterBody3D`. Двигается в плоскости XY в пределах
прямоугольника коридора. При боковом движении наклоняется по крену.
Стреляет по действию `fire` с кулдауном, пули появляются из двух точек на
крыльях. Слой столкновений `player`.

**Bullet** — `Area3D`. Летит по -Z (пуля игрока) или в сторону игрока
(пуля врага) со своей скоростью, живёт 2 секунды. При контакте с целью наносит урон и
исчезает. Пули игрока и врагов на разных слоях и масках.

**Enemy** — базовый класс, два наследника:

- `EnemyDrone`: летит прямо на игрока, 1 HP, даёт мало очков.
- `EnemyShooter`: держится впереди на фиксированной Z, стреляет в игрока
  с интервалом, 3 HP, даёт больше очков.

**Asteroid** — `Area3D` без физики, движение только кинематическое. Летит на
игрока с медленным вращением, 3 HP, при столкновении с игроком снимает 1 HP
игроку и разрушается.

**Ось «вперёд»** — стандарт Godot: камера смотрит вдоль -Z, игрок летит
в сторону -Z. Мир спавнится далеко впереди (Z = -80) и едет к игроку
в сторону +Z.

**Spawner** — раз в интервал выбирает тип объекта по весам: астероид 50,
дрон 35, стрелок 15. Спавнит на Z = -80 в случайной точке коридора.
Интервал сокращается со временем до фиксированного минимума. Волн нет.
Логика выбора вынесена в чистый класс `SpawnPolicy` для тестов.

**World** — `Node3D`. Все спавненные объекты — его дети. Каждый кадр двигает
детей на `+speed * delta` по Z и освобождает тех, кто ушёл за Z = +10. Ни
один объект сам «вперёд» не летит. Скорость читается из `GameState`.
`GameState` живёт в autoload-ноде `Session`, доступной всем сценам.

**HUD** — HP, счёт. При смерти показывает итог и кнопку рестарта.

**Управление** — InputMap-действия `move_left`, `move_right`, `move_up`,
`move_down`, `fire`. Клавиатура: WASD или стрелки плюс пробел. Геймпад:
левый стик и правый триггер или кнопка A.

**Отказоустойчивость** — если .glb модели не найден, сцена показывает
примитив-заглушку и пишет предупреждение в лог. Greybox играбелен без арта.

## 5. Пайплайн арта

### Style guide (фиксируется в `docs/style-guide.md`)

- Полигонаж: корабль игрока 400–800 треугольников, враги 150–400, астероид
  100–200.
- Shading: auto smooth 30°, без запечённых нормалей.
- Цвет: одна палитра 8×8 ячеек. Эмиссивные ячейки для двигателей и оружия.
  Один материал на все модели, ссылается на `palette.png`.
- Масштаб: 1 единица Blender = 1 метр. Корабль игрока около 4 метров в
  длину. Нос по **+Y** в Blender: экспортёр glTF переводит Blender +Y в
  glTF/Godot −Z, то есть «вперёд» (проверено экспортом тестовой стрелки
  2026-09-05, Blender 5.2.1).
- Пивот в геометрическом центре. Объект и меш названы одинаково, латиницей,
  в snake_case.

### Роль GPT через peer

Только концепты и палитры. Перед каждой моделью формируется бриф из
style-guide, через `/peer ask` запрашиваются 2–3 текстовых описания
силуэта и раскладка цветов. Если peer умеет генерировать изображения, скетч
сохраняется в `art/refs/`. Владелец выбирает вариант. Peer не работает
с Blender и с кодом игры.

### Цикл одной модели

1. Бриф и концепт от GPT, выбор владельца.
2. Claude генерирует модель Python-скриптом через Blender MCP. Скрипт
   сохраняется в `art/blender/scripts/<name>.py`, результат в
   `art/blender/<name>.blend`, рендер-превью в `art/refs/preview-<name>.png`.
3. Владелец смотрит превью или сцену, правит руками в .blend.
4. Экспорт через `art/export.py`: для каждого .blend пишет .glb в
   `game/assets/models`, применяет модификаторы, проверяет масштаб и имена.
5. Godot импортирует .glb, сцена подхватывает модель, проверка в игре.

Порядок моделей: корабль игрока, астероид, дрон, стрелок, скайбокс. Корабль
первым, потому что на нём отлаживается пайплайн.

### Blender MCP

Аддон blender-mcp (Siddharth Ahuja) с сервером через uvx, регистрируется в
Claude Code как MCP-сервер уровня проекта. Blender и аддон устанавливает
владелец по инструкции на этапе реализации. Пока MCP не подключён, скрипты
запускаются командой `blender -b -P <script>.py`.

## 6. Проверки

**Автотесты** (xUnit в `game/tests/`, без движка):

- `GameState`: урон снижает HP, ноль HP переводит в состояние смерти, счёт
  растёт, рестарт сбрасывает всё, скорость растёт до потолка.
- `SpawnPolicy`: на 1000 выборках доли типов соответствуют весам с допуском,
  интервал не падает ниже минимума.

**Проверка арта** — скрипт в `art/`, запускается через `blender -b`: каждый
.glb в `game/assets/models` содержит один меш, полигонаж в лимитах
style-guide, длина по главной оси в ожидаемом диапазоне.

**Ручная проверка** после каждого этапа: владелец играет 2–3 минуты и
отвечает на один вопрос этапа.

## 7. Этапы реализации

Каждый этап заканчивается играбельным состоянием.

1. Каркас: репозиторий, Godot-проект, CLAUDE.md, style-guide, тесты
   `GameState`.
2. Greybox: капсула летит, кубы спавнятся и едут навстречу, стрельба, урон,
   HUD, рестарт.
3. Blender MCP подключён, корабль игрока смоделирован и заменил капсулу.
4. Астероид, дрон, стрелок в игре.
5. Скайбокс, частицы выстрелов и взрывов, звук из бесплатных паков.
6. Балансировка скорости и спавна по плейтесту владельца.
