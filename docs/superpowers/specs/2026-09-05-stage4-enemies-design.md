# Этап 4: астероид, дрон, стрелок — дизайн

Дата: 2026-09-05. Статус: утверждён владельцем («ок» на предложение этапа).
Основа: спека этапа 3 `2026-09-05-stage3-blender-ship-design.md`, приём корабля
`docs/playtests/2026-09-05-ship.md`, `docs/style-guide.md`.

## 1. Цель

Все заглушки в игре заменены моделями из Blender: три варианта астероида, дрон
и стрелок. Пайплайн этапа 3 переиспользован без копирования обвязки, враги
смотрят на игрока, лимиты полигонажа проверяются автоматически.

## 2. Решения этапа

| Вопрос | Решение | Почему |
|---|---|---|
| Обвязка скриптов | `lib/pipeline.py: run(name, build_fn)` делает reset, материалы, `Builder`, `finish`, печать метрик, `.blend`, `.glb`, превью. Скрипт модели содержит только `build(b)` | Три новых скрипта, копировать 30 строк обвязки трижды нельзя |
| Астероид | Икосфера subdivisions=3 (в Blender 5.2: 1/2/3 → 20/80/320 треугольников) со смещением вершин по детерминированному шуму, три варианта `asteroid_a/b/c` из одного скрипта с разными seed | Вариативность без концепта, 320 треугольников на штуку |
| Выбор варианта в игре | `ModelSlot` получает `ModelPaths: string[]` и берёт случайный; `ModelPath` остаётся для одиночных моделей | Единственное изменение кода игры на этапе |
| Ориентация врагов | Модели строятся носом по +Y, как всё. Узел `Model` в `EnemyDrone.tscn` и `EnemyShooter.tscn` повёрнут на 180° вокруг Y, чтобы враг смотрел на игрока (+Z) | Одна конвенция для всех моделей, поворот в сцене |
| Концепт врагов | Один лист Codex с двумя врагами одной фракции в ракурсе спереди-сверху (как видит игрок) плюс лист проекций; provenance в `art/refs/` | Игрок видит врагов спереди, ракурс корабля не подходит |
| Палитра врагов | Серые корпуса (строка 4), тёмно-синие детали (строка 2), эмиссия красная и маджента (строка 7). Без кремового, оранжевого и циана | Чтение «свой / чужой» с первого кадра |
| Бюджеты | Астероид 250–600, дрон 500–800, стрелок 800–1200 треугольников | Style-guide после приёма корабля |
| Коллайдеры и баланс | Не меняются | Этап 6 |

## 4. Геометрия

### Астероид (`asteroid.py`)

- `bmesh.ops.create_icosphere(subdivisions=3, radius=1.0)` → 320 треугольников
  (в Blender 5.2: 1/2/3 → 20/80/320 треугольников).
- Смещение каждой вершины вдоль её направления на `1 + 0.35 * noise(seed, v)`,
  где шум детерминированный (`mathutils.noise.noise` с смещением по seed или
  хеш координат). Затем анизотропный масштаб, например (1.0, 0.85, 0.75) с
  перестановкой осей по seed, чтобы варианты отличались силуэтом.
- Диаметр итоговой модели около 3.0 м, коллайдер в игре сфера r 1.5 остаётся.
- Покраска: базовая `rock`; грани с нормалью вверх (`normal.z > 0.55`) `rock_light`;
  детерминированные 15 % граней `rock_dark` как пятна.
- Три варианта: seed 11, 23, 37 → `asteroid_a.glb`, `asteroid_b.glb`, `asteroid_c.glb`.
- Shade smooth by angle 30° даёт «бугристый» вид без лишних треугольников.

### Дрон (`enemy_drone.py`), по концепту

Плоский угловатый клин шире длины, один большой красный сенсор спереди,
два скошенных стабилизатора, красный двигатель сзади. Габариты около
1.6 × 1.4 × 0.5 м под коллайдер бокса (1.6, 0.6, 1.6). Нос по +Y.
Детали фиксируются в плане после выбора концепта.

### Стрелок (`enemy_shooter.py`), по концепту

Угловатый корпус с широким плечевым блоком, два маджентовых излучателя по
бокам, ряд красных сенсоров спереди, два красных двигателя сзади. Габариты
около 2.2 × 2.0 × 1.0 м под коллайдер бокса (2, 1, 2). Нос по +Y.

## 5. Игра

- `ModelSlot`: `[Export] public string[] ModelPaths = []`; если массив непустой,
  путь выбирается `Random.Shared` при `_Ready`, иначе используется `ModelPath`.
  Предупреждение о ненайденном файле по-прежнему один раз на путь.
- `Asteroid.tscn`: `Model.ModelPaths = ["res://assets/models/asteroid_a.glb", ..._b, ..._c]`.
- `EnemyDrone.tscn`, `EnemyShooter.tscn`: узел `Model` получает
  `transform = Transform3D(-1, 0, 0, 0, 1, 0, 0, 0, -1, 0, 0, 0)` (поворот на 180°
  вокруг Y). `Placeholder` под ним симметричен, визуально ничего не меняется до
  появления моделей.
- Никаких изменений в коллайдерах, спавне, HP, скорости.

## 6. Проверки

- `scripts/art.sh test`: тесты лимитов не содержат чисел из `LIMITS`.
- `scripts/art.sh check`: пять новых записей `LIMITS`, все `OK`; неизвестные
  `.glb` по-прежнему `FAIL`.
- Godot headless: без `ERROR`, без предупреждений `ModelSlot` вообще.
- Скриншот из игры на 6–8 секунде: видны астероиды разной формы, дрон и/или
  стрелок носом к камере, корабль игрока на месте.
- Владелец смотрит игру: CONTINUE или ADJUST по каждому типу модели.
